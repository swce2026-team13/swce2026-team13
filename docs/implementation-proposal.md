# 캠퍼스 길찾기 구현 제안

작성일: 2026-10-08
상태: 사용자 추가 요구를 반영하여 구현 진행. 최종 구현 범위와 제한은 루트의 `백엔드 구현.md` 참조.

## 확인한 기준

- Figma 파일: https://www.figma.com/design/ktNH70g1zWpBa3tDQKYASe/1
- 기존 프로젝트: `campass`, Next.js 16.4.0, React 19.3.0, TypeScript, Tailwind CSS 4.
- 현재 앱은 기본 템플릿이며 사용자 기능과 API가 없다.
- 디자인은 390px 너비 모바일 화면이다. 출발 위치 확인 프레임에서 배경 #F3F5F9와 최소 높이 844px를 확인했다.
- 12개 프레임의 상단과 주요 구성은 확인했다. 구현 시 긴 화면의 하단, 세부 레이어, 폰트 및 사진 원본을 추가 조사한다. 현재 모든 세부 치수나 원본 이미지 확보가 끝난 상태는 아니다.

## 구조 선택

1. **권장: 기존 Next.js + Node.js Route Handlers.** 화면과 API를 한 프로젝트에서 개발하고 배포한다. 서비스 로직과 저장소를 분리해 향후 서버 분리가 가능하게 한다.
2. Next.js + 별도 Express 서버. 별도 클라이언트가 생기면 유리하지만, 현재 범위에는 서버 실행·배포·인증 연동 작업이 추가된다.
3. 화면 시연만 구현. 디자인 확인은 빠르지만 실제 저장과 경로 계산 요구를 충족하지 못하므로 권장하지 않는다.

## 권장 구현 설계

### UI

Figma의 모바일 비율, 색상, 카드, 아이콘, 사진 배치, 한국어 문구를 재현한다. 작은 화면에서는 가로 넘침 없이 축소하고 큰 화면에서는 모바일 콘텐츠를 중앙 정렬한다. 공통 헤더·카드·진행률·지도·사진 컴포넌트를 사용하고 화면별 URL과 뒤로 가기를 지원한다. 로딩, 빈 검색 결과, 서버 오류 및 재시도 상태를 제공한다.

### 서버와 데이터

Node.js 런타임 API와 서비스 계층을 구성한다. 로컬 실행용 SQLite를 기본 제안으로 삼고, 실제 런타임과 배포 제약을 확인해 드라이버를 선택한다. 쓰기를 메모리에만 보관하지 않는다. 초기 예시 캠퍼스 데이터와 실제 사용자 활동을 구분한다.

- Building, Place: 건물, 층, 장소 종류, 검색 별칭.
- Waypoint, Edge: 안내 지점, 연결, 거리, 층 이동 방식, 접근 가능 여부, 사진 참조.
- NavigationSession: 출발지, 목적지, 옵션, 계산 경로, 현재 단계, 완료 상태.
- PassageEvent, ConfusionEvent, Feedback: 지점 통과 및 혼란 기록, 피드백 사유. 세션·지점 단위 중복 집계를 방지한다.

### API 범위

- 장소 검색과 건물·층별 조회.
- 등록된 그래프에서 경로 계산, 엘리베이터 우선 옵션, 경로 없음 응답.
- 안내 세션 생성, 단계 진행과 도착 처리, 확인된 위치부터 재계산.
- 피드백 저장 및 중복 제출 방지.
- 관리자 인증으로 보호되는 통계 조회. 혼란 비율은 같은 기간·세션·지점 기준 통과 건수와 혼란 건수로 계산하며 분모 0을 처리한다.
- 자연어 입력은 먼저 등록 장소명·별칭·키워드 기반 검색으로 처리한다. 모호한 입력은 후보를 보여 주고 확인받는다.
- 사진 처리 API는 외부 인식 제공자를 연결할 수 있게 분리한다. 제공자가 없으면 인식 불가 상태와 직접 위치 선택을 제공한다. 예시 결과를 실제 인식 성공으로 반환하지 않는다.

입력 형식·크기·유효한 장소와 단계·세션 소유권을 서버에서 검사한다. 클라이언트가 보내는 통계 값이나 인식 신뢰도를 그대로 신뢰하지 않는다. 저장 오류와 외부 제공자 실패를 구분하고 사용자에게 복구 가능한 메시지를 전달한다.

### 검증

- 경로 탐색: 정상 경로, 도달 불가, 엘리베이터 옵션, 재계산.
- 세션 및 피드백: 잘못된 단계 전환, 중복 제출, 저장 후 재조회.
- 관리자 API: 인증 실패, 중복 없는 집계, 분모 0.
- 빌드·린트와 브라우저의 검색 → 출발지 선택 → 안내 → 도착 → 피드백 흐름.
- 390px 기준 주요 화면을 Figma와 비교하고 작은 모바일 화면의 넘침을 확인.

## 보완 및 외부 연동 필요 사항

1. **실제 캠퍼스 데이터:** Figma 개요도와 일부 시설은 예시다. 실제 통로 연결, 거리, 층 정보, 통행 제한, 엘리베이터 위치의 검증이 필요하다. 초기 데이터로 계산한 경로는 현장 검증 경로가 아니다.
2. **사진 기반 위치·방향 인식:** 지점별 방향별 사진 데이터와 검증된 비전 모델 또는 외부 API가 필요하다. 디자인의 92%·89% 수치는 예시이므로 실제 신뢰도로 사용하지 않는다.
3. **자연어 의도 해석:** 등록 별칭을 넘어서는 자유로운 질문은 언어 모델 제공자와 API 설정이 필요하다. 키워드 기반 검색의 지원 범위를 명확히 표시한다.
4. **사진·폰트 원본:** Figma에서 사용한 자산을 추출할 수 있는지 확인해야 한다. 확보할 수 없는 자산은 동일 재현 불가 항목으로 보고한다.
5. **운영 환경:** 관리자 계정 운영 방식, 배포 서버, 영구 저장소, 백업, 업로드 보관 기간을 확정해야 한다. SQLite는 영구 디스크가 있는 단일 서버를 기본으로 하며 다중 인스턴스나 임시 디스크 환경에서는 별도 DB가 필요하다.
6. **현장 검증:** 실내에서 GPS만으로 방향과 층을 확정하지 않는다. 사진 인식과 경로는 실제 장소에서 정확도와 동선을 점검해야 한다.

## 납품 결과

실행 가능한 화면과 API, 데이터 초기화 및 실행 설명, 검증 결과, 구현 완료/예시 데이터/외부 연동 대기 항목을 구분한 보완 보고서를 제공한다. 현재 문서는 구현 제안이며 기능이 구현되었다는 보고서가 아니다.
